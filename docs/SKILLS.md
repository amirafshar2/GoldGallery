# 📘 همه‌ی اسکیل‌ها و استانداردهای امیر برای ساخت سایت مشتری

> این فایل را به هر AI کدنویس بده تا لازم نباشد دوباره توضیح بدهی.
> مخصوص یک پروژه نیست: برای هر سایت مشتری (طلافروشی، گالری ماشین، هر کسب‌وکار دیگر) به کار می‌رود.
> هر جا «طلا» آمده، نمونه‌ی همین پروژه است. برای کسب‌وکار دیگر، منطق دامنه‌ی خودش جایش می‌نشیند.

---

## ۰. قوانین پایه (همیشه)

1. **زبان:** همه‌ی جواب‌ها و توضیح‌ها به فارسی. رابط کاربری سایت فارسی و RTL. کد، نام متغیرها و کامنت‌ها انگلیسی.
2. **هیچ امضای AI در گیت:** هیچ `Co-Authored-By`، هیچ نام Claude یا AI در کامیت، PR یا فایل‌ها.
3. **هیچ کلید یا رمزی داخل کد:** همه در User Secrets یا متغیر محیطی. یک `.env.example` یا `appsettings.json` با مقدار خالی کافی است. اگر کلید لازم خالی بود، برنامه با پیام روشن اجرا نشود (fail-fast).
4. **تیم سه‌نفره:** قبل از هر تصمیم مهم سه نقش نظر می‌دهند:
   - **مدیر فروش:** هر صفحه یک هدف فروش دارد.
   - **مدیر طراحی:** حس لوکس و «واو» در ۵ ثانیه‌ی اول، ولی سریع روی موبایل و اینترنت ضعیف ایران.
   - **مدیر فنی:** امن، تمیز، تست‌پذیر و قابل فروش به مشتری‌های بعدی.

---

## ۱. روند کار (به همین ترتیب)

1. **تحقیق:** سایت‌های واقعی رقبا در همان صنف را ببین؛ منو، کارت محصول، صفحه‌ی محصول، اعتمادسازی و فرمول قیمت. ایده‌ی ساختار بگیر، کپی نکن.
2. **تحلیل مشتری:** پیج اینستاگرام مشتری را بررسی کن. هر هایلایت یک صفحه یا ماژول اجباری در سایت می‌شود (جدول «هایلایت → صفحه»). بعد نیازهای کشف‌شده (Pain Points) را بنویس.
3. **نقشه‌ی کار تصویری (`docs/PROJECT_MAP.md` + `.html`):** وضعیت مراحل، فهرست فایل‌ها، دیاگرام‌ها (معماری، جریان قیمت، ERD، ماشین‌های وضعیت، نقشه‌ی صفحات)، لاگ تصمیم‌ها، قدم بعدی و سؤال‌های باز.
   - **قانون:** هر جلسه **فقط نقشه** خوانده شود، نه کل پروژه.
   - بعد از هر کار، نقشه به‌روز شود و `python tools/build_map.py` نسخه‌ی HTML را بسازد.
   - فایل `CLAUDE.md` در ریشه همین قانون را به AI می‌گوید.
4. **ساخت مرحله‌به‌مرحله:** کد → تست → build سبز → تست تصویری → به‌روزرسانی نقشه. تا مرحله سبز نشده، مرحله‌ی بعد شروع نشود.
5. **تحویل:** خلاصه‌ی کوتاه فارسی، فایل‌ها در پوشه‌ی پروژه، و دستور اجرای یک‌کلیکی ویندوز (`start-dev.cmd`).

## ۴. قالب قابل فروش (White-label) — اجباری برای هر سایت

> هدف: یک سایت را بدون هیچ داده‌ای برای ۱۰ مشتری بفرستی و هر کدام سایت خودش را از پنل بسازد.

1. **همه‌چیز از پنل ادمین تغییر کند. هیچ متنی در کد ثابت نیست.** بخش‌ها (هر کدام یک سند JSON در جدول `SiteSettings`):
   - `brand`: نام، شعار، لوگو، آیکون تب
   - `theme`: رنگ‌ها `#RRGGBB`، گردی گوشه‌ها، تیره یا روشن
   - `contact`: تلفن، موبایل، واتساپ، اینستاگرام، آدرس، ساعات کاری، نقشه
   - `legal`: پروانه، کد اقتصادی، نماد اعتماد، درباره‌ی ما
   - `home`: هیرو (عنوان، متن، دکمه، تا ۷ عکس اسکرولی) + بلوک‌ها (روشن/خاموش، ترتیب، عنوان)
   - `trust`: کارت‌های مزیت
   - `footer`، `seo`
   - `features`: روشن/خاموش کردن هر بخش سایت
   - **`texts`: هر برچسب UI با کلید ثابت.** فرانت متن پیش‌فرض دارد و ادمین هر کدام را عوض می‌کند.
   - `publish`: منتشر شده یا «به‌زودی»
2. **اعتبارسنجی محتوا:** رنگ فقط Hex، URL فقط `http(s)` یا مسیر داخلی (نه `javascript:`)، سقف حجم. فقط ادمین (نه کارمند) ویرایش می‌کند. هر تغییر در Audit Log ثبت می‌شود.
3. **آپلود عکس:** بررسی Magic Bytes (فقط JPG/PNG/WebP/AVIF، SVG ممنوع)، حداکثر ۵ مگابایت، نام تصادفی، ذخیره بیرون از wwwroot، سرو با `/media/{name}` و Regex ضد Path Traversal.
4. **دو حالت نصب:** `Seed:Mode=Demo` (داده‌ی نمونه + حساب‌های دمو) و `Seed:Mode=Empty` (هیچ داده‌ای).
5. **راه‌اندازی اول (نصب خالی):** صفحه‌ی `/setup` با **کد نصب** (`Setup:Token`، مقایسه با زمان ثابت). فقط وقتی هیچ ادمین واقعی وجود ندارد کار می‌کند؛ بار دوم 409. بعد مشتری با OTP وارد می‌شود.
6. **دستیار راه‌اندازی قدم‌به‌قدم:** API `GET /admin/onboarding` وضعیت هر قدم را **از روی داده‌ی واقعی** حساب می‌کند. برای طلا ۹ قدم:
   1. نام و لوگو
   2. رنگ
   3. تماس
   4. نرخ و اجرت
   5. دسته
   6. شعبه
   7. اولین محصول و قطعه
   8. صفحه‌ی اول با عکس
   9. انتشار

   - **دسکتاپ:** پنل کنار فرم (هرگز روی دکمه‌ی ذخیره نیفتد).
   - **موبایل:** فقط در داشبورد خودش باز می‌شود؛ بقیه‌جا یک دکمه‌ی شناور «راهنما ٪».
   - نوار پیشرفت، کارت «قدم بعدی» با لینک مستقیم، تیک برای قدم‌های انجام‌شده، و دکمه‌ی «بعداً — مخفی کن» که در `onboarding` ذخیره می‌شود.
   - داشبورد هم همین چک‌لیست را نشان می‌دهد.
7. **سایت منتشرنشده:** بازدیدکننده فقط پیام «به‌زودی» می‌بیند. ادمین، کارمند، `/setup` و `/login` کار می‌کنند.

## ۵. ورود سریع دمو با یک کلیک (برای پرزنت)

- در `/login`، زیر فرم OTP، **یک دکمه برای هر نقش** (برای طلا: مشتری، همکار عمده، کارمند، ادمین). هر دکمه یک آیکون، نام نقش و یک خط توضیح دارد.
- **ریسپانسیو:**
  - موبایل: تمام‌عرض و زیر هم، ارتفاع حداقل ۴۸px
  - تبلت: ۲×۲
  - دسکتاپ: یک ردیف
- **دکمه‌ی شناور «تغییر نقش»** فقط در نشست دمو، و نوار بالای صفحه: «حالت نمایشی — داده‌ها نمونه هستند».
- **امنیت:**
  - با Flag `DemoLogin:Enabled` فعال می‌شود و پیش‌فرضش خاموش است. وقتی خاموش است، endpoint اصلاً ساخته نمی‌شود (404).
  - **Production + Flag روشن = برنامه اجرا نمی‌شود.**
  - نقش از Whitelist خوانده می‌شود و ورود فقط به حساب‌های `IsDemo` است.
  - ادمین دمو به درگاه، کلیدها و نقش کاربران واقعی دسترسی ندارد.
  - هر ورود دمو در Audit با برچسب DEMO ثبت می‌شود.
  - `/demo-roles` فقط نقش‌هایی را برمی‌گرداند که واقعاً حساب دمو دارند؛ در نصب خالی دکمه‌ای دیده نمی‌شود.

## ۶. تست CRUD تصویری کل سایت (بعد از هر مرحله، اجباری)

> «تو لوکال خودت تمام کارها را یک بار با دیدن تست کن.»

1. **یک اسکریپت** (`tests/e2e/run-visual.sh`):
   - اول پورت‌های قدیمی را آزاد می‌کند تا هرگز روی سرور کهنه تست نشود.
   - یک نصب **دمو** و یک نصب **خالی** (API + وب) بالا می‌آورد.
   - Playwright را روی **دسکتاپ (1366) و موبایل (Pixel 7)** اجرا می‌کند.
2. **پوشش:** هر عملیات ساخت/خواندن/ویرایش/حذف هر موجودیت از طریق UI واقعی:
   - دسته، شعبه، محصول، قطعه
   - محتوای سایت: نام، رنگ (چک کردن متغیر CSS)، متن‌ها
   - نرخ و قیمت‌گذاری
   - خرید کامل: سبد → قفل قیمت → درگاه آزمایشی → موفق → «سفارش‌های من»
   - کارمند وضعیت سفارش را جلو می‌برد
   - ماشین‌حساب
   - نصب خالی: «به‌زودی» → `/setup` → OTP → دستیار → قدم اول
3. **هر قدم یک اسکرین‌شات** در `tests/e2e/screenshots/{device}-{nn}-{name}.png` + گزارش HTML.
4. **دیدن واقعی:** AI باید اسکرین‌شات‌ها را **باز کند و نگاه کند**، فقط به سبز بودن تست بسنده نکند. چیزهایی که این روش پیدا کرد و تست معمولی نه:
   - CSS لود نشده
   - پنل راهنما روی دکمه‌ی ذخیره افتاده بود
   - دکمه‌های دمو در نصب خالی دیده می‌شد
   - پیام خطای انگلیسی
   - سفارش جدید پایین لیست بود
   - جدول، صفحه‌ی موبایل را زوم‌اوت می‌کرد
5. **چک ریسپانسیو:** `noHorizontalScroll` عرض صفحه را با **عرض دستگاه** (`screen.width`) مقایسه می‌کند، نه فقط `innerWidth`، چون مرورگر موبایل بی‌صدا زوم‌اوت می‌کند.
6. **Selector پایدار:** `data-testid` برای هر دکمه و ردیف مهم. اگر Selector دو چیز را پیدا کرد، داخل والد محدودش کن.

## ۸. بازار ایران (برای هر سایت فروش)

- ورود با موبایل + OTP (کاوه‌نگار یا sms.ir).
- درگاه شاپرکی با Parbad و سقف تراکنش؛ پرداخت چندمرحله‌ای، بیعانه، اقساط و فیش کارت‌به‌کارت با تأیید ادمین.
- هاست ایران + CDN داخلی (ابرآروان) + ذخیره‌سازی S3 ابرآروان.
- نماد اعتماد، پروانه‌ی کسب و کد اقتصادی در فوتر.
- نرخ مالیات و قوانین را **هاردکد نکن**؛ از پنل با تاریخ اعتبار تنظیم شود و قبل از راه‌اندازی با حسابدار یا اتحادیه تأیید شود.

### نمونه‌ی دامنه: طلافروشی
- **فرمول قیمت:**
  ```
  قیمت = وزن × نرخ ۱۸ × عیار/750 + اجرت + سود٪×(خام+اجرت) + مالیات٪×(اجرت+سود) + نگین
  ```
  گرد کردن فقط یک بار در آخر (پیش‌فرض رو به پایین).
- خرید طلای کهنه بدون اجرت حساب می‌شود.
- **محافظ نرخ:** نرخ کهنه یا جهش بیشتر از ۵٪ → فروش آنلاین متوقف و نیاز به تأیید دوم.
- **قفل قیمت (Quote):** ۱۰ دقیقه با تایمر.
- صفحه‌ی محصول = **جدول قطعه‌های یکتا** (شعبه، وزن، سایز، اجرت، قیمت، خرید) با ریز قیمت (الگوی ماوی گالری).
- منو بر سه محور: مخاطب × نوع × نیاز (کم‌اجرت، سبک، هدیه تا X).
